# Song Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Visits play one of three scored songs in turn (upper row = the score's melody, lower row = accompaniment on the bar's chord), end with "끝" and a card that names the song, and a Tab panel switches back to today's free play.

**Architecture:** Pure `Downbeat.Core` pieces (song book and validation, MIDI sample choice, a song mode inside `ConductEngine`, a `SongSession` that owns the song cursor and the song clock, a shared piece ending in `CutoffDirector`) are wired by `DownbeatApp`. Songs carry MIDI; visuals keep using a pitch step derived from it. Songs are off when `--songs off`, in strike style, or when content has no songs, and then everything is exactly as today.

**Tech Stack:** Unity 6000.3.9f1 (URP, legacy Input Manager, `JsonUtility`, `TextMesh`, IMGUI), C# NUnit EditMode/PlayMode, Node `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-01-song-mode-design.md` (Korean; section numbers below refer to it). Code map from the planning survey is summarised in each task.

Paths: `S` = `unity/Downbeat/Assets/_Project/Scripts`, `T` = `unity/Downbeat/Assets/_Project/Tests`.

- Values fixed by the spec: 96 BPM, 4/4, 16 slots per bar; songs in this order: `quiet-meadow`, `bright-morning`, `auld-lang-syne`; `conduct.songPhrases`: lowstring `[0,0,2,0]`, marimba `[1,2,3,2]`; chord-tone index 0 = bass, 1..3 = `chord[0..2]`, 4..6 = `chord[0..2]+12`; Tab panel closes after 10 s idle; switch default on (`experience.songMode = true`); `--songs on|off` beats the saved switch, which beats content.
- Free play must not change: `songs` absent/empty, `--songs off`, or strike style ⇒ identical notes to today. All existing tests stay green (baseline EditMode 1606, PlayMode 217, node 205).

- Comments and identifiers in English, matching the surrounding code's density and voice.

## Review Focus

1. A hand already in an upper cell when the visit opens: no melody before bar 1, first melody note exactly on bar 1's first score slot (Task 3, `Melody_WaitsForBarOne_WhenTheHandIsAlreadyUp`).
2. Two fists in the same frame as the song's end: one card, one "끝" (Task 4 + Task 5, `SongEnd_AndTwoFists_SameFrame_EndOnce`).
3. Switch turned off mid-song: the song plays on to its end; the next visit is free play; turned on while idle: the next visit is a song (Task 5, `Switch_AppliesFromTheNextVisit`).
4. Hands leave and come back during Settling: same visit, same song, clock not restarted (Task 5, `HandsBackWhileSettling_KeepTheSameSong`).
5. A melody note on slot 15 followed by one on slot 0 of the next bar with a 2-slot part: validation counts the gap across the bar line (Task 1, `Validation_CountsTheGapAcrossTheBarLine`).

Melody `EnergyWeight` = `ConductEnergy.Share(motion, stillPalms) × (slotsPerBar / max(IntervalOf(density), minGap[part])) / melodyNotesInThisBar`. Velocity rule unchanged (accent when the note is on slot 0).
