# 지연 시간 재는 법 (손 → 소리, 손 → 화면)

목적: 손을 내려치는 순간부터 소리가 나기까지, 그리고 화면에 반응이 보이기까지 걸리는 시간을 숫자로 남겨요. 휴대폰 슬로모션 영상에 손, 화면, 스피커를 한 장면으로 담고, 영상을 한 프레임씩 보면서 프레임 번호를 적어요. 계산은 도구(`tools/latency_from_marks.py`)가 해요. 이 문서는 Windows 노트북에서 하는 순서이고, Mac에서도 같아요.

이 방법은 앱 안의 시계가 아니라 **밖에서 본 시간**을 재요. 카메라 → 손 추적 → 앱 → 소리 장치까지 전부 들어 있는 숫자예요.

## 1. 무엇을 적나요

한 번 내려칠 때마다 영상에서 프레임 번호 3개를 읽어요.

| 이름 | 뜻 |
|---|---|
| `hand_down_frame` | 손이 **가장 아래**에 닿았다가 올라가기 시작하는 프레임 (내려치는 움직임의 맨 아래 점) |
| `sound_frame` | 소리가 **시작하는** 프레임. 영상 편집기가 보여 주는 소리 파형에서 처음 솟는 자리예요 |
| `flash_frame` | 화면 오른쪽 위의 **하얀 네모가 처음 켜진** 프레임 |

하얀 네모는 앱을 `--latency-mode` 로 켰을 때만 나와요. 손으로 친 음이 **들리는 시각**에 오른쪽 위 120×120 픽셀 흰 네모가 딱 1프레임 켜졌다 꺼져요. 소리는 그대로예요. 그래서 소리 파형의 시작과 네모가 켜진 프레임은 거의 같아야 해요(차이가 `screen_minus_sound_ms` 로 나와요).

## 2. 준비물

- 슬로모션(초당 240장)을 찍을 수 있는 휴대폰. 120장도 되지만 숫자가 거칠어요(한 프레임이 8.3 ms). 240장이면 한 프레임이 4.2 ms예요.
- 휴대폰을 세워 둘 삼각대나 책 더미. 찍는 동안 손으로 들지 않아요.
- 밝은 방. 슬로모션은 빛이 모자라면 어둡고 흐려져요.
- 노트북과 웹캠, 스피커(노트북 내장 스피커도 돼요). 헤드폰은 쓰지 않아요(소리가 영상에 안 담겨요).

## 3. 앱 켜기 (`-LatencyMode`)

화질은 평소 전시와 **같게** 해요(내장 그래픽 노트북이면 `-Backend msmf -Quality Low`). 지연은 화질에 따라 달라져요. 아래 명령의 `$extra` 에 평소 쓰던 옵션을 적어요.

```powershell
& {
  $extra = @('-Backend', 'msmf', '-Quality', 'Low')   # 평소 켜던 옵션 그대로 (없으면 @() )
  $desk = [Environment]::GetFolderPath('Desktop')
  $roots = @('C:\Downbeat', $desk) | Where-Object { Test-Path -LiteralPath $_ }   # 먼저 C:\Downbeat, 없으면 바탕화면
  $script = Get-ChildItem $roots -Recurse -Depth 3 -Filter play-with-hands.ps1 -ErrorAction SilentlyContinue | Sort-Object LastWriteTime -Descending | Select-Object -First 1
  if (-not $script) { "C:\Downbeat 와 바탕화면에서 play-with-hands.ps1 을 못 찾았어요."; return }
  powershell -ExecutionPolicy Bypass -File $script.FullName -LatencyMode @extra
}
```

손 추적과 앱이 같이 켜져요. `-LatencyMode` 는 앱에 `--latency-mode` 를 넘기고, **`--play-mode strike` 도 같이 넘겨요**: 지연은 손을 내려친 순간부터 소리까지이고, 기본인 지휘하듯 연주(`conduct`, 손을 들고 있으면 연주)에는 내려치기가 없어서 그 방식으로는 이 방법으로 잴 수 없어요. 스위치 없이 앱을 직접 켤 때는 `--latency-mode` 만 줘도 앱이 내려치기 방식으로 바꿔요. 감시 프로그램으로 켜는 `run-supervised.ps1` 에도 같은 스위치가 있지만, 재는 동안 앱이 저절로 다시 켜지지 않는 편이 낫기 때문에 여기서는 `play-with-hands.ps1` 을 써요. **이 스크립트는 Windows 노트북에서 아직 돌려 보지 못했어요**(Mac에서는 PowerShell을 돌릴 수 없어요). 안 되면 Claude에게 알려 주세요.

앱 창에서 손을 움직여 음이 나고, 오른쪽 위에 하얀 네모가 **음마다 반짝**이는지 먼저 눈으로 확인해요. 끝나면 앱 창을 닫아요(손 추적도 같이 꺼져요).

## 4. 찍는 법

한 장면에 **손, 화면(특히 오른쪽 위 모서리), 스피커**가 다 보여야 해요. 소리는 영상의 소리 칸에 담겨요.

1. 노트북 화면이 잘 보이고, 손을 내려치는 모습과 화면 오른쪽 위 모서리가 한 화면에 들어오게 휴대폰을 세워요. 화면 밝기는 최대로 해요(하얀 네모가 또렷해요).
2. 휴대폰 카메라를 **슬로모션 240fps** 로 맞추고 녹화를 시작해요.
3. 손을 한 번 내려치고, 소리가 끝날 때까지 기다린 뒤 2초 쉬고 또 쳐요. 한 영상에 10번씩 쳐요. 세 영상 이상, 모두 **30번 이상** 이 되게 해요(90백분위가 뜻을 가지려면 30번은 필요해요).
4. 친 순서대로 번호를 붙여 두어요.

슬로모션 영상은 보통 소리도 같이 느려져요(느리고 낮은 소리). 그렇지 않고 소리가 정상 속도로 들리면 그 휴대폰으로는 이 방법으로 **소리 시점을 못 읽어요**. 그때는 다른 휴대폰으로 하거나 Claude에게 알려 주세요.

## 5. 프레임 번호 읽는 법

1. 영상 편집 앱(휴대폰 갤러리의 편집, iMovie, Shotcut, DaVinci Resolve 등 소리 파형과 프레임 이동이 되는 것)에서 영상을 열어요.
2. 프레임 번호는 **영상 파일의 프레임**을 세요(240fps 영상이면 1초에 240개). 편집기가 시간(시:분:초:프레임)을 보여 주면 `초 × 240 + 프레임` 으로 바꿔서 적어요. 번호는 모두 같은 영상 안에서 같은 방식으로 세요.
3. 방향키로 한 프레임씩 움직이면서 세 가지를 찾아 번호를 적어요.
   - 손이 맨 아래에 닿는 프레임 → `hand_down_frame`
   - 소리 파형이 처음 솟는 프레임 → `sound_frame`
   - 오른쪽 위 하얀 네모가 처음 보이는 프레임 → `flash_frame`
4. 어느 칸이 확실하지 않으면 **비워 둬요.** 도구가 그 줄을 빼고 몇 줄을 뺐는지 알려 줘요. 억지로 찍은 번호보다 빈 칸이 나아요.

표 만들기 (엑셀이나 메모장, 쉼표로 나눈 글자 파일 `marks.csv`):

```
trial,hand_down_frame,sound_frame,flash_frame
1,1204,1266,1262
2,2630,2694,2689
3,4118,,4181
```

세 번째 줄처럼 소리 번호를 못 읽었으면 비워요. 맨 첫 줄(`trial,...`)은 그대로 둬요. 첫 칸 `trial` 은 영상에서 몇 번째로 친 것인지 적는 이름표예요.

## 6. 계산 (Claude가 해요)

`marks.csv` 를 Claude에게 보내 주면 아래 명령으로 계산해요. 직접 해 보고 싶으면 Mac이나 PC에서 Python 이 있으면 돼요(표준 라이브러리만 써요).

```
python tools/latency_from_marks.py --csv marks.csv --fps 240 --out result.json
```

결과(JSON)에는 이런 것이 들어 있어요.

- `hand_to_sound_ms`: 손 → 소리. 가운데값(`median`), 90백분위(`p90`), 가장 느린 값(`max`), 가장 빠른 값(`min`).
- `hand_to_screen_ms`: 손 → 화면의 하얀 네모.
- `screen_minus_sound_ms`: 화면이 소리보다 얼마나 늦나(음수면 화면이 먼저).
- `trials_used`, `rows_skipped`(빈 칸이 있어 뺀 줄), `rows_negative`(소리나 네모가 손보다 **먼저**라 읽은 번호가 잘못이라고 보고 뺀 줄), `warnings`.
- 한 번마다의 값(`trials`).

`p90` 은 90번째 백분위로, 10번 중 9번은 이 값보다 빨랐다는 뜻이에요(이웃한 두 값 사이를 직선으로 이어 계산해요).

## 7. 알아 둘 것

- 한 프레임이 `1000 / 240 = 4.17 ms` 라서, 번호를 한 칸만 잘못 읽어도 4 ms 가 흔들려요. 그래서 30번 이상을 쳐서 가운데값과 90백분위를 써요.
- 손의 "맨 아래" 와 앱이 음을 정하는 순간은 달라요. 앱은 손이 **가장 빠른 때**를 보고 음을 정하므로 맨 아래 점보다 조금 일찍이에요. 이 방법은 "맨 아래 → 소리" 를 재요. 숫자가 작거나, 드물게 음수(소리가 먼저)로 나오면 읽는 자리를 다시 확인해요.
- 화면의 하얀 네모는 모니터가 그림을 바꾸는 순간에 켜져요. 모니터와 소리 장치에 따라 둘 사이에 차이가 나는 것이 정상이에요. 그 차이를 알아보려는 것이 `screen_minus_sound_ms` 예요.
- 결과는 서류에 쓸 때 조건과 함께 적어요: 노트북 이름, 화면 방식, 화질(High/Low), 카메라 방식(`-Backend`), 휴대폰의 프레임 수, 시도 횟수.
- Mac에서 해 볼 때는 `builds/mac/Downbeat.app/Contents/MacOS/Downbeat --input hand --latency-mode` 로 앱을 켜요(손 추적은 `tracker/README.md` 대로 따로 켜요).
