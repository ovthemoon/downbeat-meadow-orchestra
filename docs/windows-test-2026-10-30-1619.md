## 2. 실패한 시험 자세히 (Mac 쪽에서 고칠 것)

### 2-1. EditMode: 가짜 파일 시스템의 경로 구분자 (21개)

- `ContentLocatorTests` 7개, `ContentValidatorNativeTests` 10개: `FakeFileProbe.Join` 은 `folder + "/" + relative` 인데 `ContentLocator`·`ContentFolderValidator` 는 `Path.Combine` 을 써서 Windows에서 `/exhibit\content`, `/app/content\content.json` 같은 열쇠를 찾아요. 가짜에는 그런 열쇠가 없어서 "content.json is missing", "folder not found" 가 돼요. 같은 검사를 진짜 디스크로 하는 `Validator_AcceptsShippedContent_OnTheRealDisk` 는 통과해요.
- `CardStoreTests` 4개: `MemoryFileSystem.GetFiles` 가 `Path.GetDirectoryName(k) == directory` 로 비교해요. Windows에서 `Path.GetDirectoryName("/data/cards/2026-10-29/a.json")` 은 `\data\cards\2026-10-29` 이고 `directory` 는 `/data/cards\2026-10-29` 라서 늘 0장이에요.
- 고칠 방법(제안): 가짜 두 개가 열쇠를 받을 때마다 `\` 를 `/` 로 바꿔 저장·비교하거나, 시험의 뿌리 경로를 `Path.Combine` 으로 만들기.

### 2-2. PlayMode (11개)

- **이 PC의 그래픽을 약하다고 본 것 (시험의 가정과 다름, 6개)**: 자동 화질이 `Intel(R) UHD Graphics` 를 약한 그래픽으로 보고 Low@0.7 에서 시작해요. 이건 의도대로예요. 그런데 시험은 강한 그래픽(High 시작)을 가정해요.
  - `AutoQualityPlayModeTests` 4개 ("this machine's graphics do not look weak": 0 이어야 하는데 4, "High" 여야 하는데 "Low", 0.85 여야 하는데 0.7)
  - `FlowerPlayModeTests.TheFlowersExist...`: `quality[0].flowerCount` 480 을 기대했는데 Low 라서 190
  - `FlowerPlayModeTests.Wake_Glints...`: 0.12초 뒤 가장 가까운 꽃봉오리가 열렸어야 하는데 0 (Low 의 꽃이 성겨서 가장 가까운 꽃이 더 멀어요).
  - 확인: 편집기를 `--quality High` 로 켜서 `FlowerPlayModeTests`·`ParticlePlayModeTests`(16개)만 다시 돌리면 꽃 시험 둘은 통과해요(15/16, 남은 1개는 아래 리본).
- **Mac 60fps 성능 시험 (4개, `GrassPerformanceTests`)**: 이 PC 편집기에서 잰 값이에요. High 28.1 fps (p95 40.6 ms), High + 입자·손 23.1 fps (p95 48.4 ms), Low 39.5 fps (p95 26.4 ms), Low + 입자·손 27.1 fps (p95 38.3 ms). 시험 이름대로 Mac 기준이라 Windows 노트북에서는 실패가 맞아요.
- **느린 프레임과 시간 (1개)**: `ParticlePlayModeTests.AHandDrawsARibbon_ThatFadesWhenTheHandIsGone`: 손을 뗀 뒤 진짜 시간 0.2초에 리본이 아직 보여야 하는데 이미 0 이었어요(Low 와 High 둘 다; Mac 에서는 통과). 손을 떼기 바로 앞에서 `MeadowCapture.Render` 로 큰 그림을 그리고 PNG로 저장하는데, 이 PC에서는 그 프레임이 길어서 다음 프레임의 `Time.deltaTime` 이 최대값(0.333초)까지 커져요. 리본은 `fadeSec` 0.5초에 사라지니까 그 0.333초에 기다린 0.2초를 더하면 이미 0.5초가 넘어요. 앱 쪽 문제가 아니라 시험이 잰 시간의 시작점 문제로 보여요(진짜 앱에서도 한 프레임이 0.5초 넘게 멈추면 리본이 그 자리에서 사라지는 정도예요).
- 고칠 방법(제안): 그래픽 가정이 있는 시험은 `LaunchArgs.OverrideForTests` 로 `--quality High` 를 주어 등급을 고정하고, 60fps 시험은 Mac에서만 돌기(`[UnityPlatform(RuntimePlatform.OSXEditor)]` 같은 것), 리본 시험은 그림을 저장한 뒤 한 프레임 쉬고(`yield return null`) 손을 떼기.

### 2-3. 감시 앱: 시험 자식 프로세스의 출력 크기 (3개)

`tests/test_output_logs.py` 의 `SPIKE` 는 `sys.stdout.write('x' * 20000 + '\n')` 이에요. Windows의 글자 모드 출력은 `\n` 을 `\r\n` 으로 써서 파일이 20002 바이트가 되고, `SPIKE_BYTES = 20001` 과 비교하는 `start_spike` 가 실패해요. 이걸 쓰는 세 시험(`test_on_windows_a_running_childs_output_file_is_not_emptied_in_place`, `test_on_posix_..._copied_and_emptied[darwin]`, `[linux]`)이 모두 여기서 멈춰요. Windows를 위한 시험이 Windows에서 돈 적이 없었던 거예요.
고칠 방법(제안): `sys.stdout.buffer.write(b'x' * 20000 + b'\n')` 로 바이트를 그대로 쓰기.

## 5. 무엇 때문에 가벼워졌나: 04:32 판과 16:19 판을 같은 조건에서

두 릴리스 판(04:32 는 바탕화면, 16:19 는 `C:\Downbeat`)을 같은 조건으로 돌렸어요: 충전기 꽂음, 손 추적은 테스트 영상(30장/초 상한), 앱은 전체 화면·소리 끔·`--quality Low`, 둘 다 내려치기 연주(04:32 는 내려치기만 있어서), 60초씩. 한 번에 하나씩만 바꿨고, 04:32 와 16:19 를 번갈아 두 번 더 돌렸어요. CPU 클럭은 기본 클럭(1.8 GHz) 대비 %(성능 카운터 `PercentProcessorPerformance`)예요.

| 판과 설정 | 손 추적 장/초 | 한 장 추론 | 앱 장/초 | 그래픽 사용률 | CPU 클럭 |
|---|---|---|---|---|---|
| 손 추적만 (앱 없음) | 28 | 31 ms | | | |
| 04:32 Low (4번) | **10.3~10.7** | 94 ms | 53 | 95~97% | **56%** |

- **가장 큰 몫: Low 를 그리는 방식 자체가 싸졌어요(10.5 → 21).** 그림 크기와 상한을 예전처럼 둬도 손 추적이 두 배예요. 그래픽 사용률은 둘 다 거의 100% 인데, 04:32 는 CPU 클럭이 기본의 56%(약 1 GHz)로 떨어지고 16:19 는 108% 를 지켜요. 사용률(바쁜 시간의 비율)은 같아도 04:32 의 그림(점마다 계산하던 구름, 기본 번짐 등)이 그래픽 칩의 전력을 더 써서, 같은 전력을 나눠 쓰는 CPU가 느려진 것으로 보여요. 그래서 손 추적의 한 장 추론이 94 ms 로 세 배가 됐어요. 이 칸에는 번짐·구름 말고도 04:32 이후의 다른 변경이 함께 들어 있어서, 무엇이 얼마인지는 더 나누지 못했어요.
- **30장 상한(21 → 24)**: 그래픽 사용률이 99% → 60%, 추론이 47 → 32 ms(손 추적 혼자일 때와 거의 같음).
- **그림 크기 0.7배(24 → 25.6)**: 그래픽 사용률 60% → 40%. 손 추적은 이미 거의 끝까지 받고 있어서 조금만 올라요.
- **손 추적 우선순위(AboveNormal)는 효과가 없었어요.** 손 추적이 CPU 차례를 기다린 게 아니라 CPU 자체가 느려진 것이라서예요.
- 04:32 의 다섯 번 중 첫 번째 한 번만 22장이었어요(나머지 넷은 10.3~10.7). 그때만 아직 전력 한도에 닿기 전이었던 것으로 보여요.

## 6. 시험의 가짜 대신 진짜 디스크로 확인한 것

2-1의 가짜 파일 시스템 시험이 실패한 기능이 Windows의 진짜 디스크에서는 되는지 봤어요.

- **내용 폴더 고르기(`ContentLocator`)**: 앱이 매번 `[content] using the content next to the program (...\builds\windows\content)` 로 실행 파일 옆 폴더를 골랐고, 사용자 폴더(`%USERPROFILE%\AppData\LocalLow\ovthemoon\Downbeat\last-known-good`)에 그 복사본(`content.json`, `audio`, `img`, `replay`)을 만들었어요.
- **오늘의 카드(`CardStore`)**: 녹화 손으로 한 번 연주하고(`--input replay --replay-loops 1`, 16초) 들판을 비워 두니, 세션이 끝난 뒤 `cards\2026-10-30\` 에 카드 하나(`.json` 4.8 kB + `.png` 320 kB)가 생겼어요. 상태 CSV: Playing → Settling → Idle, 세션 1.
